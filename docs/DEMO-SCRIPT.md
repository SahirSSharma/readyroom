# Readyroom — two-minute demonstration script

Record the real deployed app once its live YouCam integration has passed verification. Built-in samples can offer labeled saved YouCam results; explicitly choose the fresh live-preview control for the API segment below. Show a successful provider result from that recorded run. If waiting is edited down, put a visible “Processing time shortened” caption over the cut. Never replace a failed call with an unlabeled simulated or cached result.

Use a fictional built-in sample person. Keep account dashboards, API keys, personal browser tabs, and entrant identity out of the recording. Capture at a readable desktop size and show the same session throughout the pickup journey.

| Time | On screen | Narration |
| --- | --- | --- |
| 0:00–0:12 | Open fitting room with the sample rack visible. | “An interview outfit does not always need a whole new wardrobe. Sometimes it needs one missing piece. Readyroom helps someone preview that piece and follow through to pickup.” |
| 0:12–0:28 | Choose a sample person, then inspect a blazer and its measurements. | “Choose a sample person or a photograph you have permission to use. Each card represents one garment. You can inspect the source image, condition notes, and measurements before making a decision.” |
| 0:28–0:47 | Show consent, start preview, then the real processing state. | “With consent, Readyroom sends the photo and selected garment to YouCam Clothes V4. We use its outerwear category to visualize the blazer over the existing outfit. The API key stays on the server.” |
| 0:47–1:03 | Reveal the real result; compare it with source person and source garment. | “Here is the returned preview, with the source garment available for comparison. This helps someone imagine the outfit. It does not guarantee physical fit, exact garment details, or condition.” |
| 1:03–1:20 | Select demonstration pickup day, hold the garment, show pickup pass and held state. | “A preview does not reserve anything. When you choose to hold the item, Readyroom checks availability again and creates a fifteen-minute demonstration hold with a pickup pass.” |
| 1:20–1:38 | Open Pickup desk. Collect the item, then return it and show restored availability. | “The pickup desk completes the journey. Collection changes the item's status once. A return makes it available again. Uncollected holds can be released or expire automatically.” |
| 1:38–1:52 | Show demonstration notice and a brief technical proof caption. | “Every judge gets an isolated sample closet. Concurrent hold requests are protected with conditional storage writes. In our live storage check, six simultaneous requests produced exactly one hold.” |
| 1:52–2:00 | End with fitting room and brand visible. | “This is a working demonstration with fictional inventory. Readyroom connects the outfit you imagine to the exact piece you can choose, hold, and pick up.” |

## Recording checklist

- Confirm the deployed app, provider credentials, remaining credits, and the planned demonstration sample are working before recording.
- Record a genuine success; save its observed duration and returned task status as internal evidence.
- Verify the held item, pickup pass, collected state, and returned availability are visible in one session.
- Do not claim a university partnership, actual donated stock, user-study outcomes, or fit accuracy.
- Keep the final video between one and three minutes and in English.
- Publish to YouTube or Vimeo with public viewing access, then verify the exact video URL while signed out.
- Put the verified app, source, and video links in Devpost only when submission is available and eligibility requirements are addressed.
