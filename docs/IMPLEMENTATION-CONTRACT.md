# Implementation contract

Next.js App Router / TypeScript. Root owns package files, deployment, YouCam provider, assets and docs. Frontend worker owns app/page.tsx, app/layout.tsx, app/globals.css and components/. Backend worker owns lib/catalog.ts, lib/store.ts, lib/session.ts, lib/closet.ts, app/api/closet, app/api/reservations and tests/closet.test.ts. Never edit another owner's files without coordination.

GET /api/closet -> {items: Garment[], reservations: Reservation[], renderCount:number}. Establish a signed HttpOnly cookie and isolated demo workspace if absent. Return no secrets. Each visitor gets the same sample rack; reservations within that workspace persist and are concurrency safe. All views explicitly represent a demonstration.

Garment = {id,name,color,size,category:'outer',image,description,condition,measurements:{chest,length,sleeve},status:'available'|'held'|'collected',reservationId?:string}. Measurements are illustrative cm values, labeled as sample. Six items, IDs navy, charcoal, sand, olive, plaid, black. Image paths /assets/garment-{id}.png initially; root will supply assets.

Reservation = {id,itemId,itemName,pickupCode,pickupDay,status:'held'|'collected'|'released',createdAt,expiresAt}. POST /api/reservations {itemId,pickupDay} -> {reservation}. PATCH /api/reservations/[id] {action:'release'|'collect'|'return'} -> {reservation}. All writes require current workspace cookie and same-origin request. Hold TTL 15 min clearly demo. One active hold per item; repeated collect rejected. Return releases a collected item. No names/email collected.

Storage: Vercel private Blob @vercel/blob 2.8.0 with useCache:false consistent reads and ETag conditional writes, bounded retry on contention. Local development without Blob uses a local JSON file with exclusive write lock (or a small single-process lock) but production MUST fail closed without Blob. Use one state object per signed workspace; no global data leakage. Backend worker research SDK exact types. Export readWorkspace(id) and mutateWorkspace(id,fn) from store.ts for root's render accounting. Export getSession() from session.ts to root; choose return {id:string,isNew:boolean} and set the cookie there with async next/headers cookies().

Root endpoints: POST /api/tryon accepts multipart image OR sampleId with itemId and consent='true'; returns {taskId,status:'processing'}. GET /api/tryon/[taskId] -> {status:'processing'|'completed'|'failed',imageUrl?,error?,elapsedSeconds?}. Images are served only to owning workspace. Root may add GET /api/health. Frontend must show real provider errors and not substitute mock results. Sample portrait paths /assets/model-alex.png and /assets/model-jordan.png. Root will add provider/storage implementation and API evidence.

UX: Fitting room, Pickup desk, About. In the fitting room choose provided sample or upload photo with rights/processing consent; select garment, inspect illustrative measurements and condition, generate; compare source/result; reserve; pickup pass. Pickup desk operates THIS demo workspace, offers collect/release/return; visible demo notice. Need real functional controls and polished responsive design, no separate huge landing page.
